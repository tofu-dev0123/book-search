# 評価セット

検索の改善幅を nDCG@10 で測るための評価セットの設計。クエリは `eval/queries.jsonl` に置く。

## 構成

TREC 形式に合わせ、クエリと判定（qrels）を分けて持つ。

| もの | ファイル | 中身 |
|---|---|---|
| クエリ | `eval/queries.jsonl` | 検索語と、何を探しているか（意図） |
| 判定 | `eval/qrels.tsv` | クエリと書籍の組ごとの関連の度合い（0〜3） |

- 検索は投入した書誌の全体に対して行い、上位10件の ISBN を判定と照らす。判定のない書籍は関連なし（0）として扱う
- nDCG@10 はクエリごとに計算し、全クエリで平均する

## 評価用のコーパス

判定（qrels）と `target_isbn` は、投入した書誌の集合に対して付ける。途中で取り直して書誌が入れ替わると、正解の本が消えたり未判定の本が入ったりして、段階ごとの nDCG を比べられなくなる。そこで、**段階3の終わりまで次の集合を取り直さずに使う。**

| 項目 | 値 |
|---|---|
| 取得日 | 2026-11-27 |
| 取得のコマンド | `uv run fetch`（全件。[開発環境](dev-setup.md) の「書誌の投入」） |
| openBD の収録件数（`/v1/coverage`） | 約195万件（取得の前後に 1,953,608 件・1,953,696 件） |
| 書誌の件数（`data/books.jsonl` の行数） | 122,361 件 |
| ISBN 一覧のハッシュ | `0b7798cdf6b568aa56842b57ba29774cd8b915215355efcbc522570104f9a864` |

- `data/books.jsonl` は git の管理外なので、手元でバックアップを取る。失うと同じ集合は作り直せない（openBD の書誌は日々増減する）
- 手元のファイルが上の集合のままかは、ISBN 一覧のハッシュで確かめる。次のコマンドの出力が上の値と一致すればよい

```bash
python3 -c "import json,hashlib;print(hashlib.sha256('\n'.join(sorted(json.loads(l)['summary']['isbn'] for l in open('data/books.jsonl'))).encode()).hexdigest())"
```

## クエリの件数と分け方

- 30件。調整用（`dev`）20件・評価用（`test`）10件
- **`test` は重みなどの調整に使わない。各段階の最後に1回だけ測る。** 調整に使ったクエリで改善幅を報告すると、実際より大きく出るため
- `dev` と `test` は、型ごとに無作為に割り当てる。型ごとの候補の並び（`id` の順）から、Python の `random.seed(43)` のもとで `random.sample` で `test` の件数だけ選んだ

## クエリの型と配分

| 型 | `type` | 例 | 作り方 | dev | test |
|---|---|---|---|---|---|
| A. 既知の書名 | `title` | 「フーリエ解析学の序章」 | 書籍から逆に作る | 4 | 2 |
| B. 著者名 | `author` | 「若松英輔」 | 書籍から逆に作る | 3 | 1 |
| C. 話題の語 | `topic` | 「社会心理学 入門」 | 人が考える | 6 | 3 |
| D. 意図の文 | `intent` | 「子どもと一緒に読める宇宙の本」 | 人が考える | 5 | 3 |
| E. bigram の弱点 | `weakness` | 「京都」（東京都の誤ヒット）、「愛」（1文字） | 弱点に合わせて作る | 2 | 1 |

- C・D は、正解が複数あり並び順で nDCG に差が出るため厚くする。ハイブリッド検索の効果も主にここで出る
- A・B は正解がほぼ1冊で、狙った本が上位に来るかを見る
- B には、著者名の表記の違い（`Harris,Robert` 形式と、名・姓の順のクエリ）を測れるクエリを入れる
- E は [ADR-004](adr/004-japanese-tokenization.md) の見直し条件の判定に使う。件数が少ないので、平均よりクエリごとの結果を見る
- C・D は、検索結果を見る前にクエリと意図を書く。今の検索で引けるクエリに偏らせないため
- C・D は判定の基準を当てはめられる分野を中心にし、一般の読者が探しそうな分野（小説・料理など）も、意図を具体的に書いて入れる

## 判定の基準

判定するとき（人・LLM とも）はこの節に従う。

クエリの文字列ではなく、**意図（`intent`）に対して書籍がどれくらい合っているか**を、次の4段階で判定する。

| 点 | 意味 | 例（意図:「機械学習を初めて学ぶ人向けの入門書」） |
|---|---|---|
| 3 | 意図にまさに合う | 機械学習の入門書 |
| 2 | 主題は合うが、条件の一部を満たさない | 機械学習の専門書（入門ではない） |
| 1 | 主題の一部に触れる、隣の分野 | 統計学の入門書、AI 全般の読み物 |
| 0 | 関連なし | 「機械」や「学習」の語が入っているだけの本 |

- 書誌の情報（書名・著者・出版社・出版年・内容紹介）だけで判定する。検索が見ている情報とそろえるため。書誌の外の知識で点数を上げない
- 書誌から判断できない場合は、低い方の点数にする
- 同じ作品の別の版（単行本と文庫版など）は同じ点数にする。新しい版を上にするかはランキングのシグナルで扱い、判定には入れない

### 採らなかった案

- ESCI（Exact / Substitute / Complement / Irrelevant）: 商品検索向けで、「一緒に使うもの（Complement）」の判定が書籍では難しい。話題の近さで切る

## 判定の方法

- LLM が全組を判定する。「判定の基準」の節を、そのまま LLM への指示に使う
- 人は LLM の点数を見ずに、無作為に選んだ約100組を独立に判定し、LLM との一致率（重み付き κ）を記録する
- 一致率が低ければ判定の基準を直してやり直す。それでも低ければ、人が全件を確認する形に切り替える
- 前提: openBD の内容紹介を外部の LLM に送れるかを、判定の前に確認する。送れなければ人が判定する
- プールは手法を混ぜ、順番をばらして判定する。どの手法の結果かを判定に持ち込まないため

### 採らなかった案

- 人だけで判定する: 1,000〜1,500組の見込みで重い。判定者の分野の知識による、判定のぶれも出る

## プールの作り方

10万件すべてを判定することはできないので、関連がありそうな書籍（プール）を集めて判定する。プールに入らなかった書籍は関連なし（0）と見なす。

同じ `books` インデックスに、クエリの書き方だけを変えて投げて集める。

| 集め方 | 件数 |
|---|---|
| 今の検索（`multi_match`・`best_fields`・重みなし） | 上位30件 |
| タイトル・著者を重くしたもの（`title^3`・`author^2`） | 上位10件 |
| `most_fields` | 上位10件 |
| 型 A・B の狙った本（`target_isbn`） | 1件 |
| 型 D: LLM が作った言い換え3つで今の検索を引いたもの | それぞれ上位10件 |

- 重複はまとめ、どこから入ったかを `eval/pool.tsv` に残す。1クエリあたり35〜50冊、全体で約1,000〜1,500組の見込み
- 型 D の言い換えを入れるのは、語が一致しない正解を拾い、ベクトル検索の評価で不利にしないため

### 新しい手法を測るとき

- その手法の上位10件のうち未判定の書籍を判定してから、nDCG を報告する
- nDCG と一緒に judged@10（上位10件のうち判定済みの割合）を記録する。100% でなければ、nDCG は低めに出ている可能性がある

## ファイル

| ファイル | 中身 |
|---|---|
| `eval/queries.jsonl` | クエリ |
| `eval/paraphrases.jsonl` | 型 D の言い換え |
| `eval/pool.tsv` | プール（クエリ・ISBN・どこから入ったか） |
| `eval/qrels.tsv` | 判定（TREC 形式） |

`eval/` にはクエリ・ISBN・点数だけを置き、openBD の書誌の本文は含めない。

### `eval/queries.jsonl`

1行が1クエリ。

```json
{"id": "q01", "split": "dev", "type": "topic", "query": "社会心理学 入門", "intent": "社会心理学を初めて学ぶ人向けの入門書・教科書"}
```

| 項目 | 中身 |
|---|---|
| `id` | `q01` から連番 |
| `split` | `dev`（調整用）か `test`（評価用） |
| `type` | `title`・`author`・`topic`・`intent`・`weakness` |
| `query` | 検索に投げる文字列 |
| `intent` | 何を探しているか。判定の基準になる |
| `target_isbn` | 型 A・B だけに持つ。狙った本の ISBN。10万件の投入の後に確定するまでは空 |

### `eval/qrels.tsv`

TREC 形式。タブ区切りで、1行がクエリと書籍の1組。

```
q01	0	9784xxxxxxxxx	3
```

| 列 | 中身 |
|---|---|
| 1 | クエリの `id` |
| 2 | 使わない（常に `0`） |
| 3 | ISBN |
| 4 | 関連の度合い（0〜3） |
