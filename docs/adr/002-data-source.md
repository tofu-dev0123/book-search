# ADR-002: 書籍データに openBD を使う

- ステータス: 採用
- 日付: 2026-10-29
- 関連: #8

## 背景

段階1〜3 で同じ書籍データを使い、検索手法ごとの nDCG を比較する。データソースに求める要件は次のとおり。

| # | 要件 | 理由 |
|---|---|---|
| 1 | 数万件以上を一括で取得できる | 検索 API 経由で 1 件ずつ集める方式では、評価に足る件数を揃えられない |
| 2 | 内容紹介（あらすじ・紹介文）がある | 段階2 のベクトル検索と段階3 の生成検索は、タイトルだけでは意味のある比較にならない |
| 3 | 手元に保存して索引を作れる | 投入・再投入を繰り返して nDCG を測るため |
| 4 | 日本語の書籍が中心 | 日本語の分割方式（[ADR-004](004-japanese-tokenization.md)）を評価対象に含めるため |

### openBD の現状（2026-10-29 調査）

- **v1 の提供体制は 2023 年に変わっている。** JPRO から版元ドットコムへのデータ配信が 2023-06-05 に止まり、openBD は JPRO 由来データの提供を終了した。現在は、国立国会図書館の CC-BY 書誌情報をベースにした代替データと、版元ドットコム会員社の書誌・書影を配信している。代替 API は「すくなくとも60か月以上」提供すると告知されている（[openBD 2023-07-25](https://openbd.jp/news/20230725.html)、[2023-08-29](https://openbd.jp/news/20230829.html)）
- **JPRO 由来の内容紹介・目次は失われた。** カーリルの告知でも、内容紹介と目次は提供できなくなったとしている（[カーリル](https://blog.calil.jp/2023/07/openbd-v1-end.html)）
- **それでも内容紹介つきの書誌は約12万件ある。** `/v1/coverage` の収録件数は 1,946,023 件。無作為に 3,000 件を `/v1/get` で取得し、`TextContent`（TextType 02/03）が 50 文字以上ある書誌を数えたところ 185 件（6.2%）だった。全体に換算すると約 12 万件（95% 信頼区間でおよそ 10〜14 万件）になる
- **利用条件**（[openbd.jp](https://openbd.jp/)）:
  - 提供するのはデータの「利用権」で、用途は「本の販促・紹介目的に限り」
  - データの改変は禁止
  - キャッシュする場合は、変更をできるだけ早く反映する
  - 削除要請があった書誌・書影には速やかに従う

## 決定

**書籍データに openBD を使い、内容紹介つきの書誌（約10万件）を投入対象にする。**

`/v1/coverage` で ISBN の一覧を取り、`/v1/get` でまとめて取得する。投入対象は、内容紹介が一定の長さ以上ある書誌に絞る。

### 決め手

1. **一括取得を前提にした API である。** ISBN の全件一覧が取得でき、`/v1/get` は 1 リクエストで複数件を返す。openBD 自身が「全件取得やデータ同期を推奨する API 設計」としている（要件1・3）
2. **内容紹介つきの書誌が 10 万件規模で揃う。** v1 の体制変更で網羅率は下がったが、評価用データとしては足りる（要件2）
3. **日本の書籍が中心である。** サンプルの 88% が 978-4（日本）の ISBN だった（要件4）

## 検討した選択肢

### 国立国会図書館サーチ API

- 長所: 収録件数が最も多い。書誌情報は CC-BY で、利用条件が明確。
- 不採用の理由: 内容紹介をほとんど持たない（要件2）。openBD の代替データ自体がこれをベースにしており、openBD を使えば書誌部分は同等のものが得られる。

### Google Books API

- 長所: `description` を持つ書籍が多い。
- 不採用の理由: キーワード検索 API で、全件を列挙する手段がない（要件1）。利用規約上、取得したデータを保存して独自の索引を作る用途に制約がある（要件3）。

### 楽天ブックス書籍検索 API / Amazon Product Advertising API

- 長所: 商品説明を持つ。新刊の網羅性が高い。
- 不採用の理由: いずれも検索条件を指定して取得する API で、全件を列挙できない（要件1）。アフィリエイトや物販への誘導を前提にした規約で、データの保存や長期キャッシュに制約がある（要件3）。

## 結果

- 投入バッチは openBD の JSON（ONIX 形式）を読み、内容紹介は `onix.CollateralDetail.TextContent` から取り出す
- 内容紹介の有無と長さで投入対象を絞るため、収録件数（約195万件）の大半は使わない
- 内容紹介の改変が禁止されているため、検索結果には原文のまま表示する
- openBD の更新や削除要請を反映するため、再投入できる手順を用意しておく
- openBD から取得したデータはリポジトリに含めない。中間ファイルを保存する場合は git の管理外に置き、評価セットは ISBN と関連度の判定だけを持つ

## 見直し条件

- openBD の代替 API が終了する場合、または内容紹介つきの書誌が評価に足りない件数まで減った場合
- 段階3（生成検索）で、内容紹介をもとに生成した文章を表示することが「改変禁止」「販促・紹介目的に限る」に当たるかどうか判断が必要になった場合。段階3 の着手前に確認する
- 段階4（一般公開）で、利用条件との整合を確認した結果、別のデータソースや利用許諾が必要になった場合
